# Memory 使用指引

EmaAgent 的长期 Memory 是本地 Markdown，分成两条互相独立的轨道：

- `work`：用户稳定的工作偏好、协作习惯、长期约束和反复纠正。
- `relationship`：用户的共享关系信息，以及用户与每个角色之间的长期关系记忆。

Memory 不是当前代码和实时状态的事实源。仓库代码、配置、文件路径、依赖版本、任务进度和运行结果可能变化，处理当前任务时应重新读取实际代码或当前环境。

## 何时读取

以下情况通常应使用 Memory：

- 用户提到“之前”“上次”“还记得”或要求延续既有决定。
- 当前请求可能受用户长期工作偏好、禁止事项或协作方式影响。
- 当前角色需要延续与用户的称呼、边界、关系经历或未完成话题。
- 用户的要求比较模糊，而已注入摘要中出现了直接相关的线索。
- Agent 发现自己可能正在重复用户过去纠正过的行为。

以下情况通常不必检索：

- 请求完全自包含，答案不依赖用户历史。
- 当前时间、简单翻译、单句改写或其他琐碎操作。
- 需要确认的是当前代码、实时外部信息或当前运行状态；这些应直接查看事实源。

不确定时可以做一次轻量搜索，但不要把“查 Memory”变成每个请求固定执行的仪式。

## 文件布局

```text
~/.ema-agent/memories/
├─ work/
│  ├─ MEMORY.md
│  ├─ memory_summary.md
│  └─ topics/<topic>.md
└─ relationship/
   ├─ shared_user_memory.md
   ├─ character_relations.md
   ├─ memory_summary.md
   └─ characters/<character_name>/
      ├─ MEMORY.md
      └─ history/<YYYY-MM-DD>.md
```

文件职责：

- 两个 `memory_summary.md` 已随本指引注入上下文，不要为了读取同一内容再次调用工具。
- Work 的 `MEMORY.md` 和 `topics/` 保存工作偏好；Work 没有 history。
- Relationship 的 `shared_user_memory.md` 保存跨角色信息。
- `characters/<character_name>/MEMORY.md` 保存该角色与用户的稳定关系记忆。
- Relationship history 保存有回溯价值的关系经历，不代表每次对话日志。
- `.git` 和整合期间的内部文件不属于可读正式记忆。

## 工具使用

Memory 工具全部只读：

1. 通常先用 `MemorySearch` 按关键词跨轨搜索。
2. 知道目录但不知道具体文件时用 `MemoryList`。
3. 找到相关路径后用 `MemoryRead` 读取最相关的文件。
4. 优先读取一两个高相关文件；没有命中就停止，不要扫描整个 Memory 目录。

搜索词应来自当前任务与摘要中的具体概念。不要只搜索“用户”“偏好”“记忆”这类宽泛词。

## 如何使用读到的内容

- 记忆中的用户偏好可以影响工作方式，但不能覆盖用户本轮更明确、更新的要求。
- 当前用户陈述与旧记忆冲突时，以当前陈述为准；后台整合会在后续更新正式记忆。
- 关系记忆只能用于改善相处连续性，不要拿某个角色的专属经历替另一个角色说话。
- 依赖可能已变化的旧事实前先验证；不要把 Memory 内容称为“刚刚确认”的事实。
- 不要向用户机械复述“根据记忆……”。只有来源不确定或可能过时时，才需要简短说明。
- 不要因为 Memory 没有记录就断言某件事从未发生。

## 更新边界

根 Agent、Memory 工具和前端都不直接写正式记忆，也不手动创建提取、整合或维持 Job。

每条完成的 Turn 会在后台分别进行 Work 与 Relationship 提取；达到批量条件后由各自整合器更新正式文件。用户可以在文件管理器中直接修改这些 Markdown，盘上修改会在下一次整合时作为权威输入处理。

不要尝试通过终端或文件工具替后台整合器更新 Memory，除非用户明确要求直接修改本地记忆文件。
