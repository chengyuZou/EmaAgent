# Contributing

## Code formatting

Use line breaks to separate logical steps and keep expressions, function calls, and component props readable. Avoid packing multiple operations onto one line, and avoid splitting simple code unnecessarily.

## Punctuation

Use ASCII punctuation, including parentheses, brackets, and quotation marks, in code and repository-authored comments, prompts, error messages, and documentation.

Preserve user-provided content, third-party text, and literals whose exact characters are required.

## Files to exclude

Do not commit dependency directories, build outputs, temporary files, local application data, logs, credentials, or secrets.

Keep project assets, configuration files, the pnpm lockfile, and required test fixtures under version control as appropriate. Do not exclude files solely because of their extension.

## Documentation

Update the documentation affected by your changes, including relevant READMEs and examples. Keep documented behavior, commands, configuration, and defaults consistent with the code.
