# History 向上滚动时跳动

[English](../en/historyScrolling.md)

## 状态

2026-10-25, 源码修复和隔离浏览器检查通过. Dev 反馈表明滚动有所改善, 长会话持续使用和安装版验收仍未验证. 临时探针和浏览器测试夹具已经移除, 保留已有的子 Agent 测试.

## 现象与证据

在 History 中持续向上滚动时, 可见消息会突然向相反方向移位. 补入更早一页时也可能扰动阅读位置. 另有接近顶部时短暂变平稳的体感反馈, 但没有精确的时间标记.

一次记录显示, 视口上方某行从预估 112px 变为实测 65px. 同一条可见消息在视口中的位置从 73px 变为 36px, 同时 scrollTop 从 4542px 降到 4532px. 这次滚动本应让消息向下移动 10px, 额外向上位移正好为 47px, 等于预估修正的差值. 其他测量也出现 112px 变为 71px, 对应 41px 的修正.

该例没有发生补页, 采样帧中也没有活动动画. 记录中的动画属性为 color, background-color 和 opacity. 确实存在 64.5px 之类的小数高度, 但取整到 65px 不能解释几十像素的跳动. 后来一段实测高度不再变化的区间, 没有对应的消息起点移位, 与接近顶部时短暂变平稳的反馈相符.

## 已确认原因

- `useMessageViewport` 关闭了 TanStack 的行高补偿, 自己的 layout effect 又在普通用户滚动期间跳过锚点恢复. 预估高度变成实测高度时, 可见内容发生移位, 却没有对应的滚动补偿.
- 只恢复库的默认补偿, 在隔离回放中仍有较小的反向位移. 原生滚动可能在尺寸补偿写入前已经超过 TanStack 缓存的位置, 把行高差额加到旧位置上会覆盖部分正在发生的位移.
- 程序滚动通过后续事件是否命中旧目标来判断. 一次补页要求滚到 1889px, 实际位置随后为 1866px. 这个差异清掉了持续性的补页恢复状态, 此时滚动和测量仍在进行.
- wheel 事件到达处理函数时, 浏览器合成线程可能已经移动页面. 只依赖后续 scroll 事件的差值, 会漏掉用户刚好向下滚回底部的意图, 导致追加消息时仍不跟随.

## 修改

[useMessageViewport.ts](../../../../../apps/desktop/src/chat/history/useMessageViewport.ts) 保持原有接口, 负责窗口替换, 补页锚定, 消息导航和跟随意图. 行高测量由 TanStack 处理.

- 行高补偿以执行当下的实际 DOM scrollTop 为基准. 绝对导航仍使用请求的位置.
- 即时程序写入按实际造成的位移调整下一次 scroll 事件的基准. 已经发生但尚未派发事件的用户位移继续交给输入处理.
- 补页插入当次恢复原消息 ID, 后续预估修正使用库的尺寸补偿, 不再维持跨多次提交的补页模式.
- 统一处理位置范围和容差, 滚轮方向与实际位移共用跟随判断. 接近底部的 UI 继续使用 24px 阈值, 恢复跟随使用真正到达底部的 1px 容差.
- 删除独立的 initialized 标记和旧程序目标状态. 是否定位中由窗口身份和待完成导航推导. 保留有实际调用与行为需要的平滑回底重试, 以及锚点行收起后的偏移限制.

排查结束后移除临时探针, 主 History 的接入代码, 全局控制台入口和四个诊断/浏览器夹具文件. 没有修改数据库或存储格式.

## 验证

清理前, 使用假消息在独立无头 Edge 页面中通过 10 个视口场景和 4 个探针场景. 视口检查覆盖持续上滚, 滚动中补页, 接近底部时的跟随意图, 原生滚轮回到底部, 没有 pointer 事件的滚动, 阅读位置上方行高增长, 收起锚点行, 打断平滑导航, 消息/窗口导航和初始历史未加载. 两组测试包含各自的套件项, 共报告 16 项通过.

Desktop TypeScript 检查和已有的 5 个子 Agent 消息测试通过. 检查使用夹具或模拟 API, 没有访问真实用户数据库, 没有调用模型. 移除诊断代码后, 再次执行 Desktop 类型检查和已有子 Agent 测试.

安装版验收应重复长会话持续上滚, 补入旧页, 阅读时追加消息和向下滚回底部. Hook 变化后应完整刷新 Dev 页面. 曾报告的 React `Should have a queue` 错误没有在使用 React 开发构建的新隔离页面中复现; 热更新解释仍未确认, 不作为本次滚动缺陷的已确认原因.
