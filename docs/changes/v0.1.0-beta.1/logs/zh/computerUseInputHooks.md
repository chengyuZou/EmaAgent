# 电脑操控的键鼠监听与提示条绘制共用线程

[English](../en/computerUseInputHooks.md)

## 状态

2026-10-28, 源码修改完成. 编译, 默认测试和真实桌面测试 `native_desktop_round_trip` 通过. 物理键鼠接管, 混合 DPI 和安装版验收仍未验证.

## 风险与依据

这是阅读代码时发现的风险, 没有观察到实际的输入延迟.

`ema-computer-use.exe` 使用 Windows 低级键鼠钩子判断用户是否接管电脑. 低级钩子的回调由安装它的线程通过消息循环调用, 回调返回前, 系统的键鼠输入一直在等待. 原实现把钩子安装在提示条窗口所在的线程上, 而提示条每次切换状态都要逐像素计算圆角底板和光晕, 再绘制文字.

按代码中的尺寸估算, 暂停状态的提示条在 100% 缩放下约 445x128 像素, 200% 缩放下约 23 万像素, 每次绘制约需几毫秒到十几毫秒. 这一耗时是估算, 没有实测. 绘制只发生在开始, 暂停, 继续, 结束和 DPI 变化时, 目前不足以造成可察觉的延迟. 如果以后加入持续动画或扩大提示条, 钩子响应会随之变慢; 回调超时时 Windows 可能跳过甚至移除钩子.

## 修改

- [inputMonitor.rs](../../../../../apps/computer-use/src/windows/inputMonitor.rs) 新增独立的 `computer-use-input` 线程. 该线程只安装钩子并运行没有窗口的消息循环. 启动时先建立线程消息队列, 结束时收到线程退出消息后卸载钩子.
- [overlay.rs](../../../../../apps/computer-use/src/windows/overlay.rs) 不再安装钩子. 绘制拆为生成图像和显示两步, 按暂停状态, 继续快捷键是否注册成功和 DPI 缓存图像及按钮位置. 显示位置仍在每次显示时按前台窗口所在显示器计算. 操控结束, 提示条隐藏时清空缓存.
- [mod.rs](../../../../../apps/computer-use/src/windows/mod.rs) 先启动提示条线程, 再启动键鼠监听线程, 后者启动失败时关闭提示条. 退出时 `close_desktop_ui` 同时停止两个线程.

钩子回调原本只修改共享状态并投递重绘消息, 拆分后没有新增跨线程的数据传递. 通信协议, 状态通知和动作结果不变.

## 验证

测试使用本机 `cargo test` 的 debug 构建, 系统为 Windows 11 22621.

- `cargo build` 和 `cargo test` 通过, 没有编译警告. 默认测试只有一个需要桌面的忽略项.
- 在可交互桌面上运行 `native_desktop_round_trip` 通过, 用时约 1.2 秒. 测试只操作自己创建的临时编辑窗口, 覆盖两个线程的启动, 窗口截图, UI Automation, 中文输入, 暂停后旧观察失效, 结束后拒绝动作和进程退出.
- 测试导出了运行和暂停两种状态的提示条图像. 标题, 按钮, 提示文字, 蓝色底板和光晕与 README 描述一致. 测试中从暂停回到运行时使用了缓存图像; 命中缓存时不导出图像, 这一帧没有单独检查.
