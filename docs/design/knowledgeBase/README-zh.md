# 为什么删除通用 KB

[English](README.md) | [文档入口](../../README-zh.md)

我们删除了通用知识库功能. EmaAgent 是本地 Agent, 已经能够直接读取用户提供的文件, 也能由模型选择搜索词, 用 rg 在可搜索的文本中查找, 再继续阅读和提取需要的内容.

## 为什么先用现有文件工具

对当前的代码检索需求, 我们更倾向于直接, 快速的文本搜索. 用户已经有原文件, Agent 也能访问它们, 没有必要为了跟风做 RAG, 再维护另一套资料导入, 分块, 向量索引和更新流程.

我们选择先把文件读取和搜索用于实际任务. 文档发生变化时, Agent 可以继续查看当前文件, 不要求用户先把同一份资料同步到另一套知识库. 这是 EmaAgent 当前产品范围的判断, 不把通用 KB 当成必须保留的配置项.

## 接受什么限制

文本匹配可能漏掉同义表达, 模型也可能需要尝试多个搜索词和多次阅读. 文件格式和是否已有可搜索文本同样影响能做什么. 我们接受这些限制, 不把单次 rg 匹配的速度等同于整个任务的耗时或完整性保证.

如果用户提出明确需求, 并且现有读取与搜索确实无法满足, 再针对具体问题重新评估 KB. 目前不为了可能出现的需求保留整套业务.

文件读取与搜索入口见[内置工具](../../../src/builtin-tools/README-zh.md). 固定剧情的 Narrative 有自己的资料范围和检索取舍, 见[剧情检索设计](../narrative/README-zh.md).
