# 为什么用 TurnReminder 区分角色切换

[English](README.md) | [文档入口](../../README-zh.md)

同一 Session 可以先后使用不同角色. 我们希望保留已有讨论和用户决定, 同时让当前角色不要把其他角色的姓名, 职业和私人经历认成自己的.

## 为什么没有逐条重写旧消息

旧 Assistant 发言都是模型历史中的助手消息. 仅更换当前人设, 不保证模型会主动区分旧发言属于谁.

我们考虑过给旧消息逐条添加角色说明, 也尝试过在旧助手正文里加入较长的解释. 但这会改变原来的历史内容, 需要逐条判断身份, 还可能使模型把那些说明当成应当继续生成的正文.

我们选择保留已经保存的消息, 将角色交替的位置标在对话中. 这样不必为了更换角色反复改写全部历史, 原有讨论和工具事实也能继续使用.

## 为什么提醒跟随每个 Session 的 Turn

开始一个 Turn 时, 根据本 Session 上一轮的角色判断是否发生变化. 真正变化才在原有 TurnReminder 中补充切换说明, 不因全局角色按钮的变化提前插入一条提醒.

提醒划分的是相邻的角色对话区段. A 切到 B 再切回 A 时, 中间 B 的发言仍属于 B, 不能因为当前又是 A 就把全部历史归给 A. 同角色继续对话也不需要重复声明切换.

这条提醒先于本轮用户输入保存. 之后重放历史使用已经记录的边界, 不根据当前角色重新计算过去的身份. System Prompt 保留简短的当前身份要求, 具体切换边界由 Reminder 表达.

## 为什么尽量少改已有上下文

角色切换已经会改变人设等请求内容. 我们希望避免再为旧消息添加更多无必要的改写, 尽量保留没有变化的内容, 也减少对请求前缀缓存的额外干扰.

这不保证切换角色仍能命中缓存. System Prompt, 模型和供应商行为都可能影响结果. 我们选择减少不必要的历史变化, 不把某次较高缓存率当成固定效果.

## 接受什么限制

Reminder 是提供给模型的身份边界, 不是能够强制隔离所有第一人称内容的执行机制. 长历史, 摘要和角色 Prompt 的质量仍会影响表现. 我们接受需要继续观察角色效果的限制, 不将不串身份等同于角色个性已经自然生效.

切换仍应保留用户的需求, 已确认决定和工具事实. 其他角色的私人承诺和经历则不应自动由当前角色认领. 保存与历史重放约定见 [Turn](../../../src/turn/README-zh.md)和 [Context](../../../src/context/README-zh.md).
