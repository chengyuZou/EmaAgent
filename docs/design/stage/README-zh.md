# 为什么让静态立绘也参与角色表现

[English](README.md) | [文档入口](../../README-zh.md)

我们希望角色不只是摆在聊天窗口旁的一张图. 对话内容变化时, 立绘也能用表情回应, 营造类似 Galgame 中角色立绘配合台词的场景感.

## 为什么给立绘加入 emotion 映射

如果静态角色始终只显示同一张图片, 开心, 疑惑或难过都只能靠文字表达. 用户即使准备了不同表情的素材, 也需要自己切换.

因此我们让立绘按情绪分组, 用 emotion 将对话中的情绪与对应图片联系起来. 有一组表情立绘就可以获得这种表现, 不必先制作 Live2D 模型.

我们接受静态素材只能在已经提供的表现之间切换, 无法自动补出未画过的表情. 它的价值在于让台词和角色画面产生联系, 而不是保证每次情绪判断或切图都恰到好处.

## 为什么映射由角色资源决定

不同角色的素材数量和画法不同, 图片文件名也不一定能表达适合什么情绪. 我们选择让用户配置图片所对应的情绪, 角色只获得当前资源已经配置的表现名称.

这样不要求所有角色采用同一套文件命名或提供同样多的表情. 代价是导入图片后仍需要整理和配置, 配置质量会影响最终表现. 一张标签不合适的图片, 不能靠统一的情绪名称自动变得合适.

## 目前接受的表现边界

表情变化能够帮助营造场景, 但不能替代角色人设和回复本身. 模型可能选错情绪, 素材也可能不足以表达某段对话. 我们接受用户通过人设和资源配置调整效果, 不把增加映射等同于角色个性已经正确生效.

当前说话内容与 Stage 表现的归属, 在[语音设计](../speech/README-zh.md)中一起解释. 资源配置和标签用法见[角色资源](../../../src/characters/README-zh.md)及 [Stage 模块](../../../src/stage/README-zh.md).
